# Rotinas do jeito de falar: aprendizado, medida e cópias

Arquivo de apoio da skill `jeito-de-falar`, lido só para estas rotinas. Os formatos do diário estão no `SKILL.md`.

## 1. Aprendizado

- Acerto: `acertos` sobe e `revisar` vai 2 semanas à frente depois do 1º, e 4 depois do 2º; no 3º acerto, o item sai.
  Erro: volta na semana seguinte, com a formulação certa. Pulado: fica.
- Item vencido há mais de 4 semanas sai da fila, sem comentário; continua na linha do mês.
- Na revisão, até 3 itens vencidos, um por vez, como pergunta de prever ou lembrar ligada ao código real.
  O dono responde antes de ver a resposta. O retorno vem em até duas linhas.
- Se ele pular a maioria por duas semanas, proponha `professor` com "sem pergunta".
- Fora das tarefas: "quero estudar X" grava uma linha em `estudar.md`. Na revisão, ofereça um assunto: o mais antigo
  de `estudar.md` ou, com a lista vazia, uma novidade de IA ou da profissão tirada de fonte oficial, com o link.
  Explique no modo professor, no teto `conversa`. Se for novo, o dono escolhe se ele vira o item da semana.

## 2. Revisão semanal e medida

Quando: o dono diz "revisão da semana" ou aceita a oferta do fechamento. O ritmo vem do ajuste `revisao`.

1. Pergunte: "O jeito de falar ajudou a terminar o que abri? sim / em parte / não."
2. Meça com os comandos abaixo e conte as reclamações de `ciclo.md` por tipo.
3. Faça as perguntas de `aprendi.md` e ofereça o assunto de estudo (seção 1).
4. Proponha mudanças no `PERFIL.md`, no máximo o número do ajuste `revisao`, uma pergunta por vez, cada uma com motivo
   e número. Remover regra conta como mudança, e regra nova entra no lugar de outra, porque o núcleo fica em até
   50 linhas. Linhas `domino` de `conheco.md` são candidatas ao ajuste `base`.
5. Grave a linha da revisão em `ciclo.md` e a próxima data no topo de `agora.md`.

Numa cópia sem git (arquivos copiados à mão), não há PR: grave a proposta em `ciclo.md` com ajuste, valor novo, canal
e contagem. Ela vira PR numa sessão com o repositório (seção 3).

Comandos, no Git Bash; issue sempre com `-R <issues>`, PR dentro de cada repositório com PR na semana:

```bash
export LC_ALL=C.UTF-8
A=<raiz>; D=~/atlas-diario; desde=$(date -d '7 days ago' +%F)
conta_issue() { awk '/^ *```/{f=!f; next} f{next} /^(---|_Generated by .*_)$/{next} /^ *[|]/{n++; next} NF{n+=int((length+119)/120)} END{print n+0}'; }
p='^[[:space:]]*([-*]|[0-9]+[.]) '   # [.] e não \. porque awk -v trata a barra como escape
# Issue: linhas do corpo inteiro, sem desenho (teto: issue), e comentários à vista, de qualquer autor
gh issue list -R <issues> --state all --search "updated:>=$desde" -L 200 --json number -q '.[].number' |
  while read -r n; do printf 'issue %s: %s linhas, %s comentários à vista\n' "$n" \
  "$(gh issue view "$n" -R <issues> --json body -q .body | conta_issue)" "$(gh issue view "$n" -R <issues> --json comments -q '[.comments[] | select(.isMinimized | not)] | length')"; done
# Recorrente fora da regra (título sem [RECORRENTE] ou mais de um comentário à vista): sai vazio
gh issue list -R <issues> --label recorrente --state open --json number -q '.[].number' | while read -r n; do
  gh issue view "$n" -R <issues> --json number,title,comments \
    -q 'select((.title | startswith("[RECORRENTE]") | not) or ([.comments[] | select(.isMinimized | not)] | length > 1)) | .number'; done
# Relato: pontos do último comentário (teto: relato; na recorrente, o único) e links de PR
gh issue view N -R <issues> --json comments -q '.comments[-1].body' | grep -cE "$p"
gh issue view N -R <issues> --json comments -q '.comments[-1].body' | grep -c '/pull/'
# PR: pontos antes do <details> (teto: pr) e ponto "Por quê:" (mede a explicação técnica), com - ou numerado
gh pr list --state all --search "updated:>=$desde" --json number -q '.[].number' |
  while read -r n; do b=$(gh pr view "$n" --json body -q .body)
  printf 'pr %s: %s pontos, por quê: %s\n' "$n" "$(printf '%s\n' "$b" | awk -v p="$p" '/<details>/{exit} $0 ~ p {n++} END{print n+0}')" "$(printf '%s\n' "$b" | grep -cE "${p}Por quê:")"; done
# Commit: linhas de corpo sem a coautoria (teto: commit)
git log --since="$desde" --format=%h | while read -r c; do printf 'commit %s: %s\n' "$c" "$(git log -1 --format=%b "$c" | grep -vi '^co-authored-by:' | grep -c .)"; done
# Diário: linhas em Agora; qualquer linha com mais de 14 dias, Agora incluída; fechadas na semana
awk '/^## /{s=$0; next} s=="## Agora" && /^- /{n++} END{print "agora:", n+0}' "$D/agora.md"
awk -F' · ' -v d="$(date -d '14 days ago' +%F)" '/^- / && substr($1,3)<d' "$D/agora.md"
for m in $(printf '%s\n' "$(date -d "$desde" +%Y-%m)" "$(date +%Y-%m)" | sort -u); do cat "$D/$m.md" 2>/dev/null; done |
  awk -v d="$desde" '/^## /{dia=$2; next} /^- Fechada/ && dia>=d {n++} END{print "fechadas:", n+0}'
# Reclamações da semana, por tipo; Aprendi vencidos
awk -F' · ' -v d="$desde" 'substr($1,3)>=d && $2=="reclamação"{print $3}' "$D/ciclo.md" | sort | uniq -c
awk -F' · ' -v h="$(date +%F)" '{for(i=1;i<=NF;i++) if($i ~ /^revisar: / && substr($i,10,10)<=h) print}' "$D/aprendi.md"
# Núcleo (PERFIL.md, teto 50) e abertura: linhas por arquivo (alarme acima de 200, doc do Claude Code); bytes do
# AGENTS.md (Codex corta em 32 KiB); versão de cada cópia
wc -l "$A/CLAUDE.md" "$A/AGENTS.md" "$A/PERFIL.md"; wc -c "$A/AGENTS.md"
grep -m1 -H '^versão' "$A/PERFIL.md" ~/.codex/AGENTS.md "$APPDATA/devin/AGENTS.md" \
  ~/.copilot/agents/atlas.agent.md ~/.copilot/copilot-instructions.md 2>/dev/null
# Cópias da skill (a do claude.ai é a que o app baixou) contra a fonte; DIFERE pede a seção 3
F="$A/perfil/jeito-de-falar/SKILL.md"
for c in ~/.agents/skills/jeito-de-falar/SKILL.md "$APPDATA/devin/skills/jeito-de-falar/SKILL.md" \
  $(find "$APPDATA/Claude" -path '*skills/jeito-de-falar/SKILL.md' 2>/dev/null); do
  [ -f "$c" ] && { cmp -s "$F" "$c" && echo "igual: $c" || echo "DIFERE: $c"; }; done
```

Metas: zero issue acima do teto, zero recorrente fora da regra, PR com mais pontos que `pr` e commit com corpo acima
de `commit`. Agora com até 1. Zero item parado há mais de 14 dias sem decisão. Zero PR sem "Por quê:". A mesma
reclamação duas vezes no mesmo canal vira proposta. Reclamações em queda em 4 semanas. Aprendizado: acertos sobre
perguntas feitas. Abertura: nenhum arquivo acima de 200 linhas e o `AGENTS.md` longe dos 32 KiB; passou, a proposta da
semana tira texto.

- Sem `gh`: avise em uma linha, meça commits e diário, e conte a issue colando o corpo em `detalhe/corpo.md`.
- Conversa: o Git Bash não lê o transcrito, que é JSON. Vale o número gravado com a reclamação `longo`.
- No Codex o shell é PowerShell: a revisão roda no Claude Code.

## 3. Atualizar as cópias

Mudança aprovada, ou "atualiza as cópias do perfil":

1. A fonte é o `PERFIL.md` na raiz do atlas e a pasta da skill, `perfil/jeito-de-falar/`, com os dois arquivos.
   Suba a `versão` (no mesmo dia, acrescente `-b`). Numa cópia sem git, não há PR: as cópias saem dos arquivos
   copiados.
2. Depois de mesclar, copie no Git Bash o que existir nesta máquina. O Claude Code lê a fonte pelo import.
   Mudança feita na nuvem não chega às cópias: o PR pede ao dono "atualiza as cópias do perfil" numa sessão local.

   ```bash
   A=<raiz>
   D=~/atlas-diario/detalhe; mkdir -p "$D"
   # Codex: se o arquivo mudou fora da última cópia (a tela Personalization pode gravar nele), mostre e não sobrescreva
   c=~/.codex/AGENTS.md; u="$D/copia-codex.md"
   if [ -d ~/.codex ]; then
     if [ -f "$c" ] && ! cmp -s "$c" "$u"; then
       echo "$c mudou fora da cópia:"; if [ -f "$u" ]; then diff "$u" "$c"; else cat "$c"; fi
     else cp "$A/PERFIL.md" "$c" && cp "$A/PERFIL.md" "$u"; fi
   fi
   [ -d "$APPDATA/devin" ] && cp "$A/PERFIL.md" "$APPDATA/devin/AGENTS.md"
   for s in ~/.agents/skills "$APPDATA/devin/skills"; do
     [ -d "$s" ] && mkdir -p "$s/jeito-de-falar/references" && cp "$A/perfil/jeito-de-falar/SKILL.md" "$s/jeito-de-falar/" &&
       cp "$A/perfil/jeito-de-falar/references/rotinas.md" "$s/jeito-de-falar/references/"
   done
   [ -d ~/.copilot/agents ] && { printf -- '---\nname: atlas\ndescription: Perfil de comunicação do dono\n---\n\n'; cat "$A/PERFIL.md"; } > ~/.copilot/agents/atlas.agent.md
   [ -f ~/.copilot/copilot-instructions.md ] && cp "$A/PERFIL.md" ~/.copilot/copilot-instructions.md
   ```

   No claude.ai, a skill que o app usa sobe à mão: `/c/Windows/System32/tar.exe -a -c -f jeito-de-falar.zip -C
   "$A/perfil" jeito-de-falar` e, em Configurações > Habilidades > `jeito-de-falar` > ⋮ > Substituir, o `.zip`. O
   agente faz pelo Chrome do dono, com o sim dele; confere recarregando a página: o conteúdo traz a `versão` nova.
   Suba também a `versão` do `SKILL.md`: por ela se vê, em cada cópia, qual texto chegou.
3. Se o Codex mostrou diferença, o dono decide: o texto vai para o `PERFIL.md`, por PR, ou é descartado. Depois,
   rode só as duas cópias do `else`. A cópia do Codex se faz pelo Claude Code, que tem Git Bash.
4. Diga quais cópias atualizou e anote a data em `ciclo.md`.
5. Canário: em cada agente, numa conversa nova, "qual a versão do perfil?" devolve a linha `versão` da fonte.
   - Claude Code: `/context`, em Memory files, mostra o `PERFIL.md`. Na pasta do atlas, veja se ele aparece duas vezes.
   - Codex: num repositório com `AGENTS.md`; peça também "Summarize the current instructions.".
   - Devin Local: se a linha `@` do `~/.claude/CLAUDE.md` vier solta ou o núcleo vier duas vezes, ponha
     `"read_config_from": { "claude": false }` no `config.json` do Devin. Peça também "revisão da semana" e veja se
     ele lê `references/rotinas.md`. Se não ler, dê o caminho a ele.
   - VS Code, no Local agent, sem arquivo aberto e sem escolher `atlas`: abra References. Com `CLAUDE.md` e a `versão`
     certa, a linha `@` foi expandida e o agente `atlas` sobra. Com `CLAUDE.md` e sem `versão`, a linha ficou solta:
     desligue `chat.useClaudeMdFile` e use o agente `atlas`. No Agent Host, vale o `~/.copilot/copilot-instructions.md`.
